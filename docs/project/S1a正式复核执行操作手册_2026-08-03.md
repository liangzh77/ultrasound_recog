# S1a正式复核执行操作手册

## 目的

本手册用于临床完成版工作簿返回后的S1a正式语义复核。它把临床确认、冻结配置、双人独立录入、合并、盲法裁决、最终一致性统计和文档登记串成一条固定流程，避免临场凭记忆操作。

当前状态仍是等待临床回表。本文是操作手册，不代表S1a已经冻结，也不授权提前启动复核。

## 前置条件

开始正式流程前必须同时满足：

- 完成版临床确认工作簿已经收到并保存为研究产物；
- 完成版确认YAML已经按工作簿答案填写，姓名只记录为签署存在性，不进入机器结果；
- 运行Git干净，且S1a复核工作流代码已经有可冻结提交；
- 不存在未登记的真实复核响应、合并响应或裁决响应；
- 操作者准备在每个检查点追加日期日志、阶段报告和必要ADR。

## 总流程

1. 临床确认严格门通过；
2. 人工生成新的冻结复核配置；
3. 重新生成并审计伪匿名复核队列；
4. 分别启动复核者1和复核者2独立录入；
5. 两份响应完整后受控合并；
6. 对分歧字段进行盲法裁决；
7. 生成最终一致性统计；
8. 同步实验登记、主索引、日期日志、阶段报告和审计证据。

## 1. 临床确认严格门

先运行模板/完成版校验。完成版必须包含八项医学定义、八项复核参数、双角色签署、完成日期、源工作簿SHA和完成工作簿SHA。

```powershell
python tools/38_validate_annotation_clinical_confirmation.py `
  --input configs/research/annotation_clinical_confirmation_vN.yaml `
  --review-config configs/research/annotation_review_queue_vN.yaml `
  --source-workbook workspace/experiments/active/exp_2026-07_patient_multimodal_v1/reports/annotation_review/S1a临床定义与复核参数确认表_v0_2026-08-03.xlsx `
  --completed-workbook workspace/experiments/active/exp_2026-07_patient_multimodal_v1/reports/annotation_review/S1a临床定义与复核参数确认表_vN_completed.xlsx
```

通过标准：

- `ready_for_preregistration=true`；
- 报告文件名同时包含确认YAML和复核配置SHA前缀；
- 输出报告不含姓名、原始路径或自由文本隐私值；
- 若工具输出配置建议，只能作为人工生成新配置的依据，不能自动覆盖正式配置。

失败处理：

- 工作簿/YAML任一字段不一致，停止并写阴性日志；
- 临床方改变关键方法但没有真实ADR，停止并补ADR；
- 双标比例、复核人数、裁决规则或隐私边界不满足合同，停止并重新确认。

## 2. 冻结复核配置

新配置必须使用新的版本号，例如`annotation_review_queue_v1.yaml`。不得把当前v0草案简单改成`frozen_preregistered`。

必须冻结的字段：

- `status: frozen_preregistered`；
- `dataset_fingerprint`与标注版本；
- 临床确认报告SHA；
- 重新生成队列SHA；
- 队列行数；
- S1a复核工作流Git提交；
- `review_protocol.stage: semantic_presence_only`；
- `polygon_action_policy: fixed_not_applicable`；
- `geometry_reliability_stage: S1b`。

冻结后先不启动界面，先让工具做只读检查：

```powershell
python tools/35_build_annotation_review_queue.py --config configs/research/annotation_review_queue_vN.yaml
```

## 3. 生成复核队列

确认只读审计符合预期后，写出伪匿名队列：

```powershell
python tools/35_build_annotation_review_queue.py `
  --config configs/research/annotation_review_queue_vN.yaml `
  --write-draft
```

必须记录：

- 队列CSV路径和SHA；
- 队列审计JSON路径和SHA；
- 行数、唯一图像数、目标分布；
- 是否仍不含诊断、患者键、fold、旧标注答案、文件名或路径。

生成后把队列SHA和行数写回冻结配置的`frozen_provenance`，再重新计算配置SHA。此时应重新运行临床确认严格门，确保确认报告、队列和配置三者相互匹配。

## 4. 双人独立录入

复核者1：

```powershell
python tools/39_run_annotation_review_entry.py `
  --reviewer-slot 1 `
  --config configs/research/annotation_review_queue_vN.yaml `
  --queue workspace/experiments/active/exp_2026-07_patient_multimodal_v1/reports/annotation_review/annotation_review_queue_draft.csv
```

复核者2：

```powershell
python tools/39_run_annotation_review_entry.py `
  --reviewer-slot 2 `
  --config configs/research/annotation_review_queue_vN.yaml `
  --queue workspace/experiments/active/exp_2026-07_patient_multimodal_v1/reports/annotation_review/annotation_review_queue_draft.csv
```

录入规则：

- 两名复核者不能共用同一个响应文件；
- 复核者只能看到ROI、伪匿名病例号和目标；
- 备注不得写姓名、路径、原始文件名或诊断；
- ROI读取失败时不得手工绕过；
- 中断后只能用匹配清单恢复。

每次完成后记录响应CSV SHA和manifest SHA。manifest状态必须为`complete`后才能进入合并。

## 5. 合并双人响应

```powershell
python tools/40_merge_annotation_review_responses.py `
  --config configs/research/annotation_review_queue_vN.yaml
```

通过标准：

- 两份响应均完整；
- 两份响应来自同一配置和同一队列；
- 另一复核者字段和裁决字段没有出现在单人响应中；
- 合并manifest状态为`awaiting_blinded_adjudication`；
- 合并文件不能直接用于最终一致性统计。

## 6. 盲法分歧裁决

```powershell
python tools/41_run_annotation_review_adjudication.py `
  --config configs/research/annotation_review_queue_vN.yaml
```

裁决规则：

- 只裁决双方有分歧的语义字段；
- 双方一致字段不能覆盖；
- 有分歧时必须填写裁决理由；
- `presence_state`和`subtype`必须逻辑一致；
- S1a不得提交多边形动作或几何；
- 裁决manifest必须绑定配置SHA、队列SHA、合并输入SHA和裁决输出SHA。

## 7. 最终一致性统计

裁决完成后运行：

```powershell
python tools/36_validate_annotation_review_results.py `
  --config configs/research/annotation_review_queue_vN.yaml `
  --input workspace/experiments/active/exp_2026-07_patient_multimodal_v1/reports/annotation_review/annotation_review_adjudicated.csv
```

输出报告必须按输入SHA和配置SHA版本化。报告至少登记：

- 总行数、目标覆盖、隐私合同；
- 逐目标原始一致率、阳性/阴性一致率；
- Cohen's kappa和bootstrap CI；
- 分歧行数、裁决完成数；
- 失败或未达门槛原因；
- 下一步是否允许进入S1b几何可靠性预登记。

## 8. 文档和产物登记

每个正式复核检查点完成后必须更新：

- `docs/research/README.md`主索引；
- `docs/research/logs/YYYY-MM-DD.md`日期日志；
- `docs/research/experiment_ledger.yaml`，若产生正式统计；
- 独立阶段报告；
- 必要ADR；
- MLflow/Markdown双向索引，若后续进入模型实验。

完成审计命令：

```powershell
python tools/28_audit_research_documentation.py
python -m pytest -q
git diff --check
```

报告中禁止出现姓名、原始患者目录、原始图像文件名、完整原始路径或未揭示的2026标签。

## 停止条件

出现以下任一情况必须停止并记录阴性结果：

- 临床确认严格门不通过；
- 运行Git不干净或代码与冻结工作流Git不一致；
- 队列SHA或行数与冻结配置不一致；
- 任一响应文件缺manifest、manifest不匹配或状态未完成；
- 合并/裁决输入被篡改；
- 裁决未完成或试图覆盖一致字段；
- 文档审计、哈希复核或隐私检查失败；
- 临床方要求改变S1a语义范围或提前加入几何评价。

## 与S1b的边界

S1a只验证语义/存在性和子型一致性。即使S1a通过，也不能声称多边形边界可靠。S1b必须在看到几何复核结果前另行预登记抽样、工具、阈值、Dice/IoU、ROI截断和失败处理。
