# S1a临床确认机器门结果

## 结论

临床确认机器门已实现并通过空白模板正式审计。当前模板完整覆盖八项医学决定、八项复核参数、双角色签署、源/完成工作簿双哈希、数据和标注版本；隐私合同通过。

审计结果按设计为`ready_for_preregistration=false`，因为医生尚未填写回传表。这是预期的安全阴性结果，不是失败：它证明空白表无法被误认为正式临床确认，也不会自动修改复核配置。

## 研究问题与预设门槛

研究问题：能否在临床答案未知时预先建立一个机器可验证、不可绕过且不泄露身份信息的S1a冻结门？

预设门槛：

- Q1～Q8和P1～P8必须准确且唯一；
- 数据指纹、标注版本、空白源表和医生回传表哈希必须匹配；
- 完成工作簿必须是合法XLSX并含五个规定工作表，且哈希不能等于空白表；
- 医学定义、理由、参数值、临床角色和研究角色签署必须完整；
- 姓名字段、患者/图像键、私有/原始路径和绝对路径必须被拒绝；
- 偏离建议的方法选择必须引用真实存在的ADR；
- 当前代码不能表达的复核方案只能报告“不兼容”，不得生成冻结补丁；
- 验证器只能生成建议补丁，不得改写现有YAML；
- 空白模板必须验证通过但保持不可冻结。

## 成功与停止逻辑

完成确认时，CLI还要求`--completed-workbook`。全部字段通过后才可能生成只读配置建议，包括：

- `status: frozen_preregistered`；
- 复核人数、bootstrap次数和三项一致性阈值；
- 每目标旧阳性/旧未标候选数量及每折配额；
- 任一核心分歧强制裁决。

以下情况不会生成补丁：回传表等于空白表、不是有效XLSX、少工作表、双标比例低于100%、复核者不是2人、总量不能按当前8目标/2桶/5折合同平衡、取消强制裁决、改变当前CI门槛实现，或方法偏离没有真实ADR。合法但不可兼容的确认会写版本化阴性报告并返回非零退出码。

## 代码审查与验证

按正确性、可读性、架构、安全和性能五轴审查：

- 正确性：推荐路径、缺失定义、非法选项/范围、版本不符、空白表冒充回传表、偏离建议、合同不兼容均有行为测试；
- 可读性：医学选项、流程参数和允许角色由集中常量定义，CLI只负责文件边界和报告；
- 架构：复用既有`sha256_file`、研究路径和低优先级运行合同；不引入依赖、不改训练代码；
- 安全：YAML/XLSX/XML均有限制大小；XLSX只读校验容器；输出限制在研究报告目录；角色使用代码而不是姓名；
- 性能：只解析小型YAML和`xl/workbook.xml`，CPU低优先级，不使用GPU。

专项测试15项、完整测试149项通过，Python编译检查通过。审查中发现并修复：源/完成表哈希混用、伪ADR路径可提前判定ready、未限制外部文件大小、输出可指向项目任意位置、不同确认版本可能互相覆盖等问题。无未解决Critical或Important项。

## 局限性

当前CLI验证回传XLSX的容器、五页结构和文件哈希，但不自动比较Excel每个填写单元格与YAML中的机器代码和操作性定义。正式冻结时仍必须由研究负责人逐项转录/核对，并以受控研究角色完成第二签署。该限制优于自动误映射自由文本，但保留了一次人工对账步骤。
