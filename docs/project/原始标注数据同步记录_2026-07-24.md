## 患者目录匹配方法

患者目录名已经脱敏或重新编号，不能直接按目录名合并。本次使用患者目录中原始图像的完整身份进行匹配：

1. 文件名（忽略大小写）；
2. 文件大小；
3. 文件内容 SHA-256。

匹配在所有疾病目录之间全局进行，因此可以识别患者疾病分类被修正的情况。已有患者目录改为来源目录名；来源中新增加的患者目录整体复制进工作区。遇到同名但内容不同的原始图像时，同步脚本会停止，不会静默覆盖。

标注 JSON 以来源版本为准，但保留工作区已经人工确认的以下 ROI 裁剪字段：

- `ultrasound_rect`
- `ultrasound_candidates`
- `ultrasound_rect_reviewed`

## 原有数据与新增数据的结构复查

复查时将同步前工作区已经存在的 730 个患者作为“原有队列”，将本次增加的 264 个患者作为“新增队列”。

### 客户标注结构一致

两个队列使用相同的 ISAT 目录和标注结构：

```text
患者目录/
├── 原图.jpg
├── 同名标注.json
├── isat.yaml
└── mask/
    └── 同名掩膜.png
```

全量检查结果如下：

- 994 个患者目录全部含 `isat.yaml` 和 `mask/`，没有发现其他意外层级或异常顶层文件。
- 原有队列 3,420 份来源 JSON、新增队列 1,204 份 JSON 的顶层字段均为 `info + objects`。
- 两批 JSON 的 `info` 字段集合完全相同。
- 两批标注对象均使用相同的 `area、bbox、category、group、iscrowd、layer、note、segmentation` 字段。
- 11,077 个标注对象的 `segmentation` 都采用相同的多边形二维列表格式。
- 新增队列出现的 8 种 `isat.yaml` 内容版本全部可以在原有队列中找到，没有出现新的标注工具格式。

因此，客户对旧数据和新增数据使用的是同一种标注方法，不需要转换 JSON、mask 或患者目录结构。

### ROI 裁剪字段是本项目的后处理

工作区原有数据中有 3,419 份 JSON 包含：

- `ultrasound_rect`
- `ultrasound_candidates`
- `ultrasound_rect_reviewed`

新增 1,204 份 JSON 均不包含这些字段。这不是客户标注结构变化，而是原有数据后来通过本项目的 `annotation_viewer.py` 单独做过超声有效视野裁剪。新增数据保持无裁剪字段是正常的；运行裁剪程序自动框选并人工确认后，字段会写入对应 JSON。

当前有 1,203 个“图像和 JSON 已配对、但尚无 `ultrasound_rect`”的可裁剪样本，其中新增队列 1,202 个、原有队列 1 个。不要为了表面统一而填入整图矩形；ROI 训练脚本会直接要求有效的 `ultrasound_rect`。

随后已通过“自动框选全部”为 1,203 个配对样本生成初始裁剪框。它们进入人工检查时
使用 `ultrasound_rect_reviewed = false`；数量会随着人工确认逐步减少。查看器已将原来的筛选入口明确拆分为：

- “未裁剪”：没有 `ultrasound_rect`；
- “未确认”：启用按钮时，对已有 `ultrasound_rect` 但尚未人工确认的图片生成固定快照。

在“未确认”快照中打开一张图片就会写入
`ultrasound_rect_reviewed = true`。为支持快速浏览后回头复查，已经查看的图片不会
从本轮文件列表中消失；文件名由橙色（未确认）变为绿色（已确认）。关闭“未确认”
后再次启用，程序才会按当前数据状态生成新快照，此时已确认图片不再显示。

人工确认导航按“疾病 → 患者 → 图片”稳定排序；一个疾病处理完成后会自动展开后续疾病，
跳过本轮快照中没有图片的疾病。保存裁剪框时保留当前快照节点，并继续定位下一张，
避免 Qt 文件树因动态隐藏节点而回退到已经完成的疾病。

|---|---:|---:|

新增队列的 87 张未标注图像主要来自：

- 滑膜囊肿：62 张，涉及 6 个患者目录；
- 类风湿性关节炎：22 张，涉及 4 个患者目录；

`tools/01_clean_labels.py` 只把图像与 JSON 同名配对的样本放入清洗数据，因此这些未配对文件不会混入训练，但也不会得到利用。是否补标应由标注人员确认，不能自动生成像素标注。

新增队列另有 7 份 JSON 没有对应 mask、1 个 mask 没有对应 JSON。当前训练与转换主流程以 JSON 多边形为准，因此缺 mask 不阻塞训练；如果以后直接使用 ISAT mask，应先补齐。

### 旧处理痕迹与标签清洗

同步备份显示，旧工作区有 181 份 JSON 曾包含旧式 `cropped` 标志。这是早期裁剪处理遗留字段，不属于客户 ISAT 格式；当前同步已统一使用 `ultrasound_rect`，不需要恢复 `cropped`。

客户增量数据还重新带入了两个明确错别字：

- `SPA-斌下肾囊炎` → `SPA-髌下深囊炎`
- `GA股二头肌建` → `GA股二头肌腱`

这两项已加入 `src/label_mapping.py` 的清洗映射，并由单元测试覆盖。原始 JSON 保持来源原貌，重新生成 `cleaned` 时会自动修正，避免错误标签成为独立训练类别。

同步前 86 类缓存与同步后 88 类缓存的精确差异为：

- 新出现 `GA股二头肌建`，1 个标注对象；这是 `GA股二头肌腱` 的错别字。
- 新出现 `SPA-斌下肾囊炎`，6 个标注对象；同时原来的正确类别 `SPA-髌下深囊炎` 消失，因此这是名称被错误版本替换，类别总数净变化为 0。
- 新出现 `损伤-半月板囊肿`，5 个标注对象；没有发现对应的旧名称或清洗映射，属于本批数据真正新增的类别。

仅将这两个错别字在原始标注中原位修正后，语义上相对于旧数据仍会增加两个类别：`GA股二头肌腱` 和 `损伤-半月板囊肿`，所以标注查看器缓存仍会是 88 类，只是类别名称正确。完整运行 `tools/01_clean_labels.py` 时还会合并其他历史别名；当前 dry-run 得到的训练用清洗类别数为 86 类。

后续研究决定像素区域标签不再携带疾病前缀。更新清洗规则后，88 个原始类别会规范化为 28 个疾病无关类别；这里记录的 86 类是此前“仅修复错别字、仍保留疾病前缀”的历史中间状态。完整映射见 `docs/project/像素区域标签规范化记录_2026-07-24.md`。

## 对已有训练数据的影响

原始数据目录已更新，但历史模型和实验产物没有修改。当前训练脚本读取的是：

```text
workspace/data/shared_derived/cleaned
workspace/data/shared_derived/splits
```

这两处仍然对应同步前的患者目录名和旧患者集合。尤其需要注意：

- `tools/01_clean_labels.py` 会写入 `cleaned`，但不会先清空旧目录；直接覆盖运行会留下旧目录名，形成重复或陈旧样本。
- `tools/02_split_dataset.py` 把患者目录名作为患者标识，并把相对路径写入拆分文件；旧拆分在目录重命名后已经失效。

开始新的训练尝试前，应在保留历史实验产物的前提下重新生成一套干净的派生数据：

1. 归档或更换旧的 `shared_derived/cleaned` 输出位置，不要在含旧文件的目录上增量覆盖。
2. 重新运行 `tools/01_clean_labels.py`，生成清洗数据、类别映射和清洗报告。
3. 重新运行 `tools/02_split_dataset.py`，按新的 994 个患者重新划分训练、验证和测试集合。
4. 根据训练方法重新运行所需格式转换脚本（COCO、YOLO、nnU-Net 或 MedSAM）。
5. 建立新的实验目录进行训练，旧实验作为历史结果保留。

将 Excel 信息用于训练时，还需要统一处理日期、年龄、空值和文本格式；不要直接把 Excel 原始字符串送入模型。

## 重复执行

同步工具支持先预演、确认无冲突后再执行：

```powershell
python tools/sync_new_raw_data.py
python tools/sync_new_raw_data.py --apply
```

脚本会排除 `膝关节2026未标注`，并把来源根目录元数据放到 `workspace/data/raw/`。
