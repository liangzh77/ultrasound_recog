随机化验项遮蔽及 `p=0.15` 已登记为推荐的稳健性实验，并保留 `p=0` 对照；具体概率在实现训练流程时确认，不把它写成已经获得确认的固定参数。

|---|---:|---|

## 二、明确发现的标签泄漏

### 2.1 “诊断”列完整暴露主要诊断

新版 Excel 中的诊断信息不是偶尔存在：

- 本轮纳入的 767/767 人，“诊断”均非空；
- 痛风组写有“痛风”“痛风、OA”等；
- OA 组写有“OA”等；
- RA 组写有“RA”“RA、OA”“RA、AS”等；
- SPA 组写有 AS、PsA、银屑病关节炎、反应性关节炎、SpA 等；
- 损伤组 71 人全部写为“损伤”。

因此，“诊断”只能用于构建真值、合并症审计和错误分析，绝不能进入模型特征。

诊断列还记录了不完整的合并症信息，例如：

- 痛风组有 7 条同时写 OA；
- RA 组有 53 条诊断文本包含 OA；
- SPA 组有 3 条诊断文本包含 OA。

这些信息不是系统采集的完整多标签真值，不能据此训练“是否合并 OA”的监督任务。

### 2.2 身份字段也暴露类别

- 痛风、OA、RA、SPA 的编号分别以 `GA`、`OA`、`RA`、`SPA` 开头；
- 损伤表第一列虽然名为“姓名”，实际值为“损伤1、损伤2……”。

因此编号、姓名、患者目录名、文件路径和文件名都只能用于连接记录及患者级分组，不能转成模型输入。

### 2.3 “病程”存在少量直接线索和大量定义风险

767 人的病程字段中：

- 642 条是可以识别的纯时长；
- 97 条缺失；
- 28 条是叙述文本或不能按纯时长直接解析；
- 其中 7 条明确包含“银屑病”“外伤”或“骨折”等类别线索。

代表性问题包括：

```text
银屑病7年，膝关节疼痛9月
外伤后左膝痛3月
外伤后左膝肿痛伴活动受限1天，髁间骨折
```

即使只剩一个时长数字，病程仍可能是医生在已知诊断后回顾性填写的“疾病病程”，而不是模型实际使用时可独立获得的“症状持续时间”。两者含义不同。

结论：

- 主结果暂时排除原始病程字段；
- 不能把病程原文送入文本模型；
- 只有客户确认其定义为“超声检查前、与诊断名称无关的症状持续时间”后，才能生成纯数值 `symptom_duration_days`，作为预设的次要消融实验；
- 含疾病名、病因、手术或影像描述的病程行一律置为缺失，不做 NLP 特征。

### 2.4 超声检查日期属于批次信息

当前没有单独的“诊断日期”字段，只有“超声检查日期”。该字段不进入训练。

日期不仅临床价值低，还能暴露采集批次：

- GA、OA、RA、SPA 主要来自 2024–2025 年；
- 损伤组横跨 2022–2026 年。

模型很容易把年份当成疾病类别捷径。日期只能用于数据质控、时间外验证和追踪数据版本。

### 2.5 原始像素区域标签仍然暴露疾病

当前原始 JSON 仍保存 88 个带疾病前缀或历史写法的类别，例如：

```text
RA骨皮质
OA骨赘
GA积液
SPA-滑膜
N骨皮质
```

虽然 2026-07-24 已完成 88 → 28 类的规则审计，但目前：

- `workspace/data/shared_derived/clean_report.json` 仍标记为 `dry_run=true`；
- `workspace/data/shared_derived/category_mapping.json` 仍是旧的 84 个疾病前缀类别；
- 旧 `cleaned/` 只有 3,419 份 JSON，未覆盖当前完整数据。

因此 28 类目前只是已经验证的转换规则，并未真正更新训练产物。若直接使用现有类别缓存训练，仍会发生严重标签泄漏。

正式训练分割或病变模块前必须重新运行非 dry-run 清洗，确认：

- 类别缓存为 28 类；
- 所有有效 JSON 均已重新生成；
- 规范化类别中不含 GA、OA、RA、SPA、N、损伤等疾病前缀；
- 诊断模型若使用病变特征，只能使用自动模型预测出的疾病无关类别，不能使用人工真值区域名。

## 三、哪些 Excel 信息适合训练

### 3.1 主模型建议白名单

异常五分类的图像 + 临床融合模型可使用：

| 字段 | 建议 | 处理方式 |
|---|---|---|
| 性别 | 使用 | 二分类或类别编码；同时做性别分层评估 |
| 年龄 | 使用 | 去掉“岁”，转为数值；训练折内标准化 |
| 血沉 ESR | 使用 | 数值化，保留单位 mm/h |
| CRP | 使用 | 数值化，保留单位 mg/L |
| ACCP / 抗 CCP | 使用 | 统一命名、单位和上下限表达 |
| RF | 使用 | 数值化，统一 `<`、`>` 限值 |
| HLA-B27 | 使用 | 阳性/阴性编码；缺失单独处理 |
| 尿酸 | 使用 | 数值化并确认单位 |

这些化验项目是合法的临床预测因子，前提是模型部署时能够在诊断前获得它们。由于它们本身也可能参与医生建立最终诊断，研究结果应称为“图像 + 临床化验辅助主要诊断”，不能解释为独立的影像诊断能力。

### 3.2 主模型明确黑名单

以下信息不进入模型张量：

```text
编号、姓名、患者目录名、图像文件名、完整路径
诊断及诊断文本中的合并症
病程原始文本
超声检查日期或诊断日期
原始疾病前缀区域标签
Excel 是否存在
数据来源批次
```

其中编号仍可作为连接键，诊断仍可作为监督真值，日期仍可用于时间外验证，但这些用途必须与模型特征隔离。

### 3.3 病程只做次要消融

在客户确认定义后，可以增加一个预先限定的消融实验：

```text
symptom_duration_days
```

要求：

- 只接受纯时长；
- 年、月、周、天统一换算；
- 不保留原始文本；
- 不从“银屑病”“外伤”“骨折”等词生成特征；
- 与不使用病程的主模型使用相同患者折比较；
- 若只在内部数据上有增益、在隐藏队列上无增益，则不进入最终模型。

## 四、化验缺失本身也是类别线索

当前不同疾病的检查完整性差异很大：

| 队列 | 平均已有化验项数（共 6 项） | 六项全有 | 典型现象 |
|---|---:|---:|---|
| 痛风 | 3.40 | 29/129 | 尿酸几乎都有，其他项目约一半缺失 |
| OA | 3.58 | 34/212 | HLA-B27 缺失 81.6% |
| RA | 5.21 | 75/261 | ESR、CRP、CCP、RF 几乎完整 |
| SPA | 5.55 | 68/94 | HLA-B27 有记录 93.6% |
| 损伤 | 1.21 | 3/71 | 多数炎症/免疫化验未检查 |

只根据 ESR、CRP、CCP、RF、HLA-B27、尿酸“是否有值”组成 6 位缺失模式，在当前 767 人上做一个描述性表内多数类规则，准确率可达到 56.1%；最大类别的无信息基线只有 34.0%。这不是交叉验证成绩，只用于证明“医生给谁开了什么检查”已经包含很强的疾病工作流信号。

因此建议：

1. 主结果使用训练折内插补，不把缺失指示器作为显式特征；
2. 建议训练中对每个已有化验值以初始 `p=0.15` 独立随机遮蔽，降低模型对固定检查套餐的依赖；验证和推理时关闭，并保留 `p=0` 对照；
3. 单独报告“仅缺失模式”基线；
4. 再做“加入缺失指示器”的敏感性实验，若提升主要来自缺失模式，不把该结果作为核心医学性能；
5. 所有插补、缩放、限值处理和编码器只在当前训练折拟合；
6. 隐藏的 2026 队列必须按真实临床缺失模式验证。

## 五、正常组无 Excel 的处理

正常组没有 Excel，不能训练一个直接读取“Excel 是否存在”的六分类模型，否则模型会学到：

```text
无 Excel = 正常
```

继续采用分层融合：

```text
P(正常) = P_image(正常)

P(疾病 d) =
    (1 - P_image(正常)) × P_fusion(d | 异常)

d ∈ {RA, GA, SPA, OA, 损伤}
```

- 正常/异常只由患者级图像模型判断；
- Excel 只参与异常患者内部的五分类；
- 如果以后取得正常组同标准、同流程的化验数据，再研究直接六分类多模态融合。

## 六、人口学偏差需要单独测量

当前队列人口学分布差异明显：

| 队列 | 男/女 | 平均年龄 |
|---|---:|---:|
| 痛风 | 129/0 | 44.3 |
| OA | 46/166 | 66.2 |
| RA | 51/210 | 59.0 |
| SPA | 57/37 | 45.6 |
| 损伤 | 24/47 | 41.1 |

性别和年龄在医学上可以使用，但也可能让模型依赖本队列构成。例如痛风组目前全部为男性。应固定报告：

- 仅年龄 + 性别基线；
- 仅化验基线；
- 图像基线；
- 图像 + 年龄/性别；
- 图像 + 全部允许临床字段；
- 按性别和年龄段分层的灵敏度、特异度和校准。

## 七、推荐的训练输入接口

临床特征处理器只接收明确白名单：

```text
age_years
sex
esr_mm_h
crp_mg_l
anti_ccp_u_ml
rf_iu_ml
hla_b27
uric_acid
```

可选实验字段：

```text
symptom_duration_days
```

`person_key` 只用于 Excel 连接、患者级分折和结果追踪，不进入特征矩阵。

建议在代码中建立自动测试：

- 任何列名匹配 `诊断|编号|姓名|日期|路径|文件名` 时拒绝训练；
- 任何像素区域类别仍含疾病前缀时拒绝训练；
- 正常/异常模型若读取临床字段或 Excel 存在性时拒绝训练；
- 每一折保存实际使用的字段白名单、插补参数和数据哈希。

## 八、执行顺序

1. 先重新生成 28 类疾病无关的 cleaned 标注和类别缓存；
2. 构建只读患者 manifest，明确区分连接键、真值和模型特征；
3. 先完成仅图像的患者级六分类；
4. 建立年龄/性别、化验值和缺失模式三个表格基线；
5. 训练异常五类图像 + 临床晚期融合；
6. 通过分层概率得到最终六分类；
7. 病程仅在客户确认字段定义后进入次要消融。
