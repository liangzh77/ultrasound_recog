# S1a盲法分歧裁决工程准备结果

## 结论

S1a盲法分歧裁决工程已准备完成。两名复核者完成独立响应并由受控合并器生成待裁决文件后，裁决者只能看到伪匿名病例号、目标、人工确认ROI和两位复核者的代码结论；不能看到诊断、旧标注、姓名、文件名或原始路径。界面只允许修改双方有分歧的语义字段，双方一致的字段被禁用，S1a仍不记录任何多边形几何。

真实裁决仍被临床确认硬门锁定。当前`annotation_review_queue_v0.yaml`仍是`draft_not_preregistered`，所以正式启动器会在写入任何裁决文件前拒绝运行。

## 研究问题与预设门槛

研究问题：能否在不破坏双人独立复核和诊断盲法的前提下，建立一个可恢复、可审计、只处理分歧字段的S1a裁决链？

预设工程门槛：

- 裁决输入必须来自受控合并文件`annotation_review_merged_for_adjudication.csv`及其清单；
- 配置必须为`frozen_preregistered`，并绑定完成临床确认报告SHA、队列SHA/行数和复核工作流Git；
- 运行Git必须干净，裁决相关代码内容必须与冻结工作流Git一致；
- 合并清单必须绑定配置SHA、队列SHA和合并CSV哈希；
- 裁决文件只能写入受控文件名`annotation_review_adjudicated.csv`；
- 只允许裁决双方分歧的`presence_state`、`image_mode`、`annotation_scope`和`subtype`；
- 双方一致字段不得被覆盖；有分歧时必须填写裁决理由；
- `presence_state`和`subtype`必须逻辑一致：阳性不能是`not_applicable`，阴性或不在视野必须是`not_applicable`，不确定只能配`uncertain`或`not_applicable`；
- S1a裁决不得提交`polygon_action`或任何几何坐标；
- 输出清单必须记录配置、队列、合并输入、裁决输出、Git、运行时间、隐私边界和进度。

## 代码审查

按正确性、可读性、架构、安全和性能五轴审查：

- 正确性：分歧字段和一致字段被严格区分，最终裁决还会再次验证存在状态/子型一致性；
- 可读性：裁决UI、启动器、领域验证和统计门控分开，沿用原公共CSV字段；
- 架构：裁决只消费合并响应，不接触原始私有关联，不把S1b几何职责放回S1a；
- 安全：受控文件名、哈希清单、干净Git、路径/姓名过滤和ROI失败禁用形成多层边界；
- 性能：裁决窗口一次只加载一张ROI，CSV/JSON产物小，不占GPU。

无未解决Critical或Important项。Qt窗口类仍偏长，但当前复杂度主要来自布局和交互状态；如果后续增加S1b几何工具，应新建独立界面而不是继续扩展S1a裁决窗口。
