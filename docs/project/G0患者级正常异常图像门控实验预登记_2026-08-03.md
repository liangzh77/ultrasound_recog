## 假设与待确认边界

1. “正常”目录是本轮主要诊断的正常参考；RA、GA、SPA、OA、损伤五类均合并为“异常”。
2. G0 只回答患者级正常/异常，不重新解释五种异常主诊断，也不推翻 E1/E2/E2-R/E3 的六分类阴性结论。
3. 继续使用固定 967 名患者、4,543 张图像和原有外层五折；不重分患者，不读取 2026 隐藏标签。
4. 输入仍是人工确认 ROI、等比例 letterbox 到 384×384，不读 ROI 外像素，不加入 Excel、文件名、路径、图像尺寸或缺失模式。
5. 只允许一个候选：EfficientNet-B2 + 患者级 gated attention MIL + 固定 0.05 归一化注意力 KL；从相同 ImageNet 权重初始化，不用已训练六分类权重热启动。
6. 每折训练目标不超过 10 小时，11.5 小时软停、23.5 小时硬停；CPU/内存/GPU 保护继续遵守 ADR-003。
7. 若任一正式门槛失败，G0 作为阴性实验保留，不搜索第二个骨干、聚合器、损失、输入尺寸或 KL 强度。

## Objective

研究问题：去掉五种异常主要诊断之间的单标签冲突后，仅用同一患者的全部 ROI 图像，能否稳定估计患者为正常或异常的概率，并为后续分层融合提供不依赖 Excel 存在性的图像门控？

预设假设：六分类模型在异常亚型间表现不足，不等于正常/异常图像信号无效。专门的二分类患者级目标应提高异常检出稳定性和概率校准，同时固定熵正则避免模型系统性只依赖单张图。

G0 通过后只开放后续 F0～F2 的实现/预登记：

- G0 输出 `P(正常 | 图像)` 与 `P(异常 | 图像)`；
- F0～F2 再在异常条件下预测 RA、GA、SPA、OA、损伤；
- 最终六类概率按条件概率相乘并归一，不把“有没有 Excel”作为正常标签。

G0 不是可独立临床诊断的模型，也不直接生成 2026 预测。

## 冻结设计

| 项目 | 草案冻结值 |
|---|---|
| 实验代码 | `G0` |
| 任务 | 患者级正常/异常二分类 |
| 开发数据 | 967 名患者；正常 200、异常 767；4,543 张图像 |
| 数据指纹 | `62ecb01c4d77ec0012704611ecc8d18ef51ebb4e0ea744fb3896948829f0b675` |
| 外层验证 | 固定 fold 0～4；每名患者只出现在一个外层测试折 |
| seeds | 20260724～20260728，与对应外层 fold 绑定 |
| 图像输入 | 人工确认 ROI；384×384 等比例 letterbox；不加边距 |
| 每轮 bag | 训练最多随机 6 张；验证/测试使用全部合格图像 |
| 骨干 | `efficientnet_b2.ra_in1k` |
| 聚合 | gated attention；attention dim 256 |
| 正则 | 归一化 `KL(attention || uniform)`，固定权重 0.05 |
| 头 | dropout 0.30 + 二分类线性头 |
| 优化 | AdamW；encoder LR 1e-4；head LR 3e-4；weight decay 1e-4 |
| 训练 | 最多 60 epochs；warmup 3；patience 10；AMP；effective patient batch 8 |
| 资源 pilot | fold 0、5 epochs；不评价外层测试；通过后才能正式五折 |
| 2026 队列 | 完全隔离；不得生成或查看参考标准 |

bag 标签来自患者主要诊断：正常为 0，其他五类为 1。单张图不当作独立患者，患者采样和所有指标均以患者为单位。Attention MIL 采用置换不变 bag 聚合；注意力只能解释为模型内部权重，不能解释为病变定位。方法依据是 [Ilse 等人的 Attention-based Deep Multiple Instance Learning](https://proceedings.mlr.press/v80/ilse18a.html)。

## 阈值和校准

每个外层 fold 内只用训练部分训练模型，并沿用既有内层验证进行早停。二分类操作阈值只能在该 fold 的内层验证预测上选择：在异常灵敏度不低于 0.90 的候选阈值中最大化正常特异度；若不存在满足者，该 fold 固定使用 0.5 并登记门槛失败。外层测试折不能参与早停、阈值或温度选择。

概率校准只允许温度缩放，温度也只能在内层验证上拟合。报告校准前和校准后的 OOF；正式六类条件概率组合只能使用校准后的 G0 概率。

## 预设通过门槛

以下条件必须同时满足：

1. 数据、身份、ROI、fold、外层隔离、配置和产物哈希合同全部通过；
2. pooled OOF ROC-AUC 不低于 0.80，患者 bootstrap 95% CI 下限不低于 0.75；
3. 按内层验证冻结阈值合并 OOF 后，异常灵敏度不低于 0.90，正常特异度不低于 0.50；
4. 二分类 macro-F1 不低于 0.70；
5. 至少 4/5 折 ROC-AUC 不低于 0.75；
6. 温度缩放后 ECE 不高于 0.10，Brier score 不高于 0.15，且二者均不得较校准前恶化；
7. 多图患者中最大注意力不低于 0.95 的比例不超过 0.50；
8. 每折正式训练不超过 11.5 小时软限制，峰值 GPU 显存不超过 9 GB，资源守卫未持续压满 CPU/内存；
9. 失败、提前停止、重启和拒绝启动的 run 全部登记，不删除不利结果。

这些是研究晋级门，不代表临床应用阈值。G0 通过只能说明可以预登记 F0～F2，不能直接冻结最终诊断系统。

## 对照和报告

- 无信息对照：按开发集患病率输出恒定异常概率；
- 参考对照：把既有 E2-R 严格 OOF 的六类概率折叠为正常/异常，只作事后参考，不作为改变 G0 门槛或搜索模型的依据；
- 主报告：pooled OOF ROC-AUC、PR-AUC、macro-F1、balanced accuracy、异常灵敏度、正常特异度、Brier、ECE和 95% CI；
- 分层报告：fold、性别、年龄段、患者图像数和 ROI 长宽比分层；分层只解释偏差，不据此调参；
- 错误审计：假阴性异常患者和假阳性正常患者的伪匿名汇总，不记录姓名、原始文件名或路径。

正式报告遵循 TRIPOD+AI 的透明报告原则，并以 PROBAST+AI 的 participants、predictors、outcome、analysis 四域检查偏倚；两者分别见 [TRIPOD+AI](https://www.bmj.com/content/385/bmj-2023-078378) 和 [PROBAST+AI](https://www.bmj.com/content/388/bmj-2024-082505)。

## Code Style

核心概率合同使用显式名称和强校验，不用含混的类别编号：

```python
def compose_gate_probabilities(prob_normal: float) -> tuple[float, float]:
    if not 0.0 <= prob_normal <= 1.0:
        raise ValueError("prob_normal must be in [0, 1]")
    return prob_normal, 1.0 - prob_normal
```

输出只包含伪匿名键、fold、真实二分类代码、预测代码和概率；内部诊断目录、原始路径、文件名和 Excel 内容不得写入公开 OOF。

## Testing Strategy

- 单元测试：二分类标签映射、概率和、bag 顺序不变、padding 忽略、KL、阈值只用内层验证、温度只用内层验证；
- 合同测试：外层测试不进入训练/早停/阈值/校准，OOF 恰好覆盖 967 名患者且无重复；
- 隐私测试：公开 OOF、summary、MLflow 参数和异常信息不含姓名、原始目录、文件名、Excel 内容或 2026 标签；
- 资源测试：pilot 不迭代外层测试，峰值显存、CPU 持续压力、内存和运行时间均登记；
- 统计测试：bootstrap 固定 seed，AUC/PR-AUC/灵敏度/特异度/Brier/ECE 的合成样本结果可复核；
- 回归测试：完整测试套件和研究文档链接审计通过。

## Boundaries

### Always

- 先提交冻结配置和实现，再从干净 Git 启动正式 run；
- 每折完成后登记 Git、配置 SHA、fold/seed、权重 SHA、运行时间、硬件、OOF SHA、MLflow run ID、失败原因和下一步；
- 保留所有阴性、失败和被资源门拒绝的 run；
- 每个检查点同步主索引、日期日志、实施计划和独立阶段报告。

### Ask first

- 改任一正式门槛、标签定义、骨干、损失、KL 权重、输入几何或运行预算；
- G0 失败后提出第二候选；
- 提前进入 F0～F2 或生成 2026 预测。

### Never

- 用 2026 标签选择阈值、模型或停止规则；
- 把 Excel 是否存在输入 G0；
- 把图像当患者拆分，或让同一患者跨 fold；
- 把注意力权重称为病灶定位或临床解释；
- 在报告、Git 或 MLflow 泄露姓名和原始路径。
