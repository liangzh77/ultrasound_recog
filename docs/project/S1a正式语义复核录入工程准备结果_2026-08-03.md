# S1a正式语义复核录入工程准备结果

## 结论

S1a正式语义复核的录入工程已准备完成，但真实录入仍被临床确认硬门锁定。两位复核者将分别使用独立响应文件，只看到伪匿名病例号、目标和人工确认ROI；另一复核者答案、裁决、诊断、旧标注、文件名和路径均不可见。响应按次原子保存并绑定配置、队列、Git和哈希，完整后才允许合并进入裁决。

方法审计同时发现原草案把“旧多边形不可见”和“选择保留/调整、报告Dice/IoU”放在同一阶段，合同不自洽。依据[ADR-012](../decisions/ADR-012-拆分S1a语义复核与S1b几何可靠性复核.md)，S1a只评价语义/存在性；`polygon_action`固定为`not_applicable`。独立新绘多边形与Dice/IoU改在S1a通过后的S1b单独预登记，不能把本工程结果解释为几何可靠性已经验证。

## 研究问题与预设门槛

研究问题：能否在临床定义尚未确认时提前完成一个不会越过硬门、不会破坏复核者独立性且能可靠恢复进度的正式录入链？

预设工程门槛：

- 配置状态必须为`frozen_preregistered`；当前Draft必须在创建响应文件前拒绝；
- 必须绑定完成临床确认报告SHA、重新生成的队列SHA/行数和复核工作流代码基线Git；
- 运行Git必须干净，录入/合并代码内容必须与冻结工作流Git一致；
- 队列每行必须严格要求两名独立复核者，响应行数和队列SHA必须与冻结证明一致；
- 每个响应文件只能包含自己的槽位，另一复核者和裁决字段必须为空；
- 只记录四项必填语义代码和可选安全备注；S1a不得记录多边形动作或几何；
- ROI读取失败时禁用表单；禁止绝对路径、私有路径和姓名相关值；
- 每次保存使用稳定CSV字段和原子替换，并生成哈希绑定的隐私/进度清单；
- 两份响应必须都完整、同配置、同队列且哈希匹配后才能合并。
