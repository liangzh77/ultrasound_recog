# ADR-011：临床确认通过机器门后才允许冻结S1a

## 状态

Accepted

## 日期

2026-08-03

## 背景

S1审计证明旧28类标注存在类别重叠、支持不足和明显的诊断相关标注流程偏差。ADR-010因此要求先冻结临床本体、阴性和重叠协议。S1a已经形成400图盲法队列、结果验收器、只读ROI预览和临床确认工作簿，但八项医学定义与八项复核参数尚未获得书面确认。

若研究人员直接在`annotation_review_queue_v0.yaml`中把`pending_clinical_confirmation`改为数字，或把工作簿中的自由文本临时转述为配置，就可能出现以下问题：

- 空白表和医生回传表无法区分，或回传件版本不可追溯；
- 医学定义、阈值、签署和数据版本不完整仍被误标为“已冻结”；
- 低于建议门槛或改变双标方案时没有独立方法决定；
- 验证工具直接改写配置，掩盖人工选择和失败路径；
- 姓名、患者标识或原始路径进入Git或研究报告。

## 决策

S1a正式预登记前增加一个只读、fail-closed的临床确认机器门：

1. 使用`annotation_clinical_confirmation_v0.yaml`完整登记Q1～Q8医学决定、P1～P8复核参数、临床角色和研究角色签署；
2. 同时绑定空白源工作簿和医生完成工作簿的独立SHA-256；完成工作簿必须与空白表不同；
3. 绑定数据指纹、标注版本、源Git提交、复核配置和确认YAML哈希；
4. 只允许受控角色代码进入机器记录，不登记医生姓名；拒绝绝对路径、私有字段和患者/图像标识字段；
5. 若选择偏离研究建议，必须提供已存在的ADR；仅填写一个看似合法的ADR路径不算通过；
6. 若图像总数不能按8目标×2抽样桶×5折平衡、复核人数不是2、不是全部双标、允许核心分歧不裁决，或改变当前95% CI/点估计门槛合同，则报告“需要修改合同”，不生成配置补丁；
7. 验证器只生成`proposed_review_config_patch`，绝不修改`annotation_review_queue_v0.yaml`；
8. 验证报告按确认YAML哈希命名，保留不同版本、阴性和被拒绝路线；
9. 正式冻结仍需研究负责人把回传工作簿逐项转录/核对到YAML并完成双角色签署。

## 备选方案

### 直接修改复核YAML

实现最快，但不能证明临床答案、签署和回传工作簿版本，容易把草案追认为预登记。拒绝。

### 直接从Excel自动写入正式配置

可以减少转录，但当前“最终选择”和操作性定义包含自由文本，且医疗决定需要研究负责人确认语义，不适合一次性自动改写正式配置。暂不采用；后续可增加只读单元格对账，但仍不得自动落盘冻结。

### 沿用建议值启动复核

会把研究建议冒充临床共识，并允许在结果出现后重解释标签。拒绝。

## 后果

- 临床答案回来后，冻结过程可复核且不能误触发；
- 合同不兼容或偏离建议的选择会显式停止，并要求代码修改或新ADR；
- 空白模板当前可以通过结构审计，但必须保持`ready_for_preregistration=false`；
- 验证器不自动比较Excel每个填写单元格与YAML文本，正式冻结前仍有一次由研究负责人执行的人工对账；这一限制必须保留在阶段报告和最终报告中；
- 机器门属于研究治理工具，不是模型实验，不产生MLflow、OOF或权重。
