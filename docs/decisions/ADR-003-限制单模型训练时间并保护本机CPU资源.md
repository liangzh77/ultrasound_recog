# ADR-003：限制单模型训练时间并保护本机 CPU 资源

## 状态

Accepted

## 日期

2026-07-24

## 背景

本轮研究在本机执行：

- GPU：NVIDIA GeForce RTX 3080，10 GB；
- CPU：Intel Core i5-10400，6 核 12 线程；
- 内存：32 GB；
- 当前剩余磁盘约 39.5 GB。

项目负责人要求：

- 选择模型和训练方案时同时考虑识别性能和本机资源；
- 训练不能让 CPU 长时间满载，电脑在训练期间仍应可以正常使用；
- 每次训练一个模型不得超过 24 小时；
- 单次训练最好不超过 12 小时。

本决策中的“一次训练”定义为一个配置、一个 outer fold、一个随机种子的独立训练 run。五个 fold 顺序执行，不能并行启动五个训练进程。

## 决策

### 1. 模型选择

- 主骨干固定为 `efficientnet_b2.ra_in1k`，输入 384 × 384；
- 患者 MIL 训练时每轮每名患者最多随机使用 6 张图，推理时仍使用全部合格图像；
- `convnext_tiny.fb_in1k` 只作为受控挑战模型；
- ConvNeXt 的资源试运行若预测单 fold 超过 10 小时或峰值显存超过 9 GB，则取消该挑战实验；
- v1.0 不进行 448 输入实验；
- 不做 EfficientNet 与 ConvNeXt 的跨骨干集成；最终只保留选定骨干的五折模型集成。

### 2. CPU 和内存保护

默认资源参数：

```text
DataLoader num_workers = 2
prefetch_factor = 2
persistent_workers = true
torch intra-op threads = 4
torch inter-op threads = 1
OMP_NUM_THREADS = 2
MKL_NUM_THREADS = 2
OPENBLAS_NUM_THREADS = 2
NUMEXPR_NUM_THREADS = 2
```

其他限制：

- 不并行训练多个 fold 或多个模型；
- 训练进程使用 Windows BelowNormal 优先级；
- OpenCV 内部线程关闭，避免与 DataLoader/BLAS 过度竞争；
- 启动训练前可用内存至少 8 GB；
- 可用内存低于 4 GB 时在安全检查点停止；
- CPU 平均使用率持续 5 分钟超过 80% 时告警并在下一 epoch 停止，随后使用 `num_workers=1` 恢复；
- 只有 CPU 平均低于 65%、可用内存超过 10 GB 时才允许试用 `num_workers=3`，上限不超过 3；
- 数据预处理、哈希扫描、分割转换和模型训练不同时运行。

实现说明（2026-08-02）：资源守卫必须跨epoch保存压力开始时间；单次1秒采样超过80%只开始观察窗口，不得立即停止。E2 fold 0首次正式尝试因旧实现把一次100%采样误判为持续压力而安全停止，外层test未迭代；修复后从已保存状态恢复。该失败尝试永久保留在研究日志和结构化台账中。

### 3. GPU 保护

- 使用 FP16 AMP；
- 单进程显存预算不超过约 9 GB，为桌面和 CUDA 波动保留空间；
- OOM 时依次降低同批患者数、采用梯度累积、降低每步 bag 实例数；
- 不先降低输入尺寸，避免改变已冻结的可比实验；
- 记录 GPU 利用率、显存、温度和功耗；
- 温度超过 83°C 持续时告警，超过 88°C 持续 5 分钟时安全停止。

### 4. 单 run 时间守卫

- 资源试运行：5 epoch，最多 1 小时；
- 正式 run 目标：不超过 10 小时；
- 11.5 小时达到软截止：完成当前 epoch、保存最佳模型和状态后退出；
- 23.5 小时达到外部硬截止：watchdog 终止仍未退出的进程；
- 退出状态明确标记为 `COMPLETED`、`EARLY_STOPPED`、`TIME_BUDGET_REACHED` 或 `RESOURCE_GUARD_STOPPED`；
- 时间到达不是自动延长的理由；必须先分析收敛曲线和瓶颈，再决定是否调整 epoch、冻结层数或取消模型。

### 5. 测量后再调整

每种新架构先运行单 fold 的 5 epoch 资源试验，记录：

- 每 epoch 时间；
- 预计达到早停和最大 epoch 的总时间；
- GPU 峰值显存和平均利用率；
- CPU 平均/峰值利用率；
- 可用内存最低值；
- 数据读取等待比例。

只有资源试验通过后才启动五折。资源优化顺序是：

1. 调整 DataLoader worker 和线程；
2. 使用 AMP、梯度累积和冻结 encoder；
3. 减少训练 bag 中每步实例数；
4. 降低最大 epoch 或加强合理早停；
5. 取消资源代价过大的挑战模型。

不以取消患者级五折、使用外层测试折早停或查看 2026 参考标准换取速度。

## 备选方案

### 并行训练五个 fold

- 优点：墙钟时间短。
- 缺点：单张 10 GB GPU 无法合理并行，CPU、内存和磁盘 I/O 会明显争抢。
- 结论：拒绝。

### 使用更大模型或 448/512 输入

- 优点：理论上可能提高细节识别。
- 缺点：显存、时间和过拟合风险增加，且会扩大实验矩阵。
- 结论：v1.0 拒绝；只有 384 主线完成且资源余量充足时另立实验。

### 为赶时间减少五折

- 优点：训练次数少。
- 缺点：损伤、SPA 等小类别的结果更不稳定，破坏既定研究设计。
- 结论：拒绝；应减少挑战模型，而不是减少主要五折。

### CPU 满载以提高 GPU 吞吐

- 优点：可能略微减少数据等待。
- 缺点：影响用户正常使用，并可能因内存压力降低整体稳定性。
- 结论：拒绝；宁可接受少量 GPU 等待。

## 后果

### 正面影响

- 每个 run 有明确可预测的时间边界；
- 电脑训练期间仍可正常使用；
- 资源不足时能够安全保存并退出；
- 优先保证主要五折和患者级研究设计；
- 模型精度比较不会被同时改变输入尺寸、预训练来源等因素污染。

### 成本和限制

- 总五折训练仍可能跨越数天，但每个 run 不会长期失控；
- GPU 利用率可能不是始终 100%；
- 取消大模型或更高分辨率后，可能放弃少量潜在精度；
- 需要实现资源监控和时间 watchdog。
